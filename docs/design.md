# CareerLens 系统设计

日期：2026-10-16。依据已认可的产品范围实施，用户明确要求直接编写代码，不再进行可视化设计确认。

## 目标与边界

面向大学生的本地求职训练应用。离线完成简历导入、岗位能力提取、证据匹配、材料诊断、自适应文字面试、训练报告。单用户本地部署，默认仅监听 127.0.0.1。模型文件和 Python 依赖在首次安装时准备，运行阶段不使用云 API。

## 架构与技术决策

浏览器原生 HTML/CSS/JavaScript → FastAPI 同源 API → 业务服务 → SQLite、文件解析器、Ollama。静态资源随项目分发，无 CDN、前端构建或外部字体依赖。Python 3.10+；SQLite 持久化 JSON 快照及关系外键。Ollama 使用非流式 /api/chat 和 JSON Schema。默认 qwen2.5:3b，6 GB 显存从 4096 上下文起；8–12 GB 可尝试 qwen2.5:7b。显存占用还取决于上下文、运行时及其他进程，不能只按模型文件大小判断。

## 业务数据与一致性

- projects：名称、原始简历、岗位描述、版本、当前分析 ID、时间。
- analyses：项目 ID、材料版本、结构化要求、引用、诊断、评分、引擎、耗时、原始材料快照。
- sessions：项目 ID、分析 ID、目标轮数、当前题、已答轮次、状态、版本。
- 每个回答保存题目、答案、六维评分、依据、改进建议、训练重点。
- 编辑材料清空当前分析链接，历史面试继续使用创建时的分析快照。
- 乐观版本锁防止双击、并发请求覆盖答案。模型调用不持有数据库事务，提交前再次校验版本。
- 项目删除级联删除分析和会话，不保存原始上传文件。

## 分析算法

模型提取岗位要求及 required/preferred 权重，提供岗位原句与简历原句。服务器核验引用是原材料的连续子串；无法定位的引用丢弃并显示告警。重复要求合并；每项最多三条证据。技能仅出现在技能列表标记为 mentioned；出现在含行动描述的项目/经历中标记 proven；无证据标记 missing。覆盖分=100×Σ(权重×状态值)/Σ权重，required=2，preferred=1；proven=1，mentioned=0.4，missing=0。该分数是解释性证据覆盖指标，不能表示录用概率。要求本身没有有效岗位原文时丢弃，全部无效则返回模型格式错误。

RAG 使用项目材料与内置面试指南，中文字符二元组及英文词分词、BM25 检索；用户材料与指南分区，指南不能充当个人经历证明。检索文本仅作为数据，提示词要求忽略其中的指令。保留输入长度上限，避免长文静默截断；超限需用户精简。

## 面试状态机

active → paused → active；完成设定轮数后 completed。启动需已有有效分析。首题来自岗位缺口和经历；每轮模型返回六维 0–5 分、理由、亮点、建议、下一题及训练重点。固定模板约束只问一个问题；评分为模型辅助判断，不用于企业筛人。面试答案的新经历视为待补充信息，不能自动写入简历。暂停后拒绝回答；恢复后继续同一题。

## 输入输出与异常

PDF 文本型提取，扫描件或不可提取 PDF 提示 OCR，不承诺自动识别。DOCX 保留段落和表格文本；TXT 支持 UTF-8/GB18030。10 MB 文件上限、压缩展开限制、文本上限；解析后用户复核再保存。页面全部使用 textContent 渲染用户和模型内容；导出 HTML 进行转义，通过浏览器打印保存 PDF。

Ollama 不可达/缺模型/超时/返回非法 JSON 均给出可操作错误；不静默降级为规则模式。仅允许 loopback Ollama 地址，HTTP 客户端禁用环境代理。规则模式必须显式配置，所有结果携带引擎标识。默认无外部监听和跨域访问，不实现多租户认证。仅允许同源浏览器写请求。

## UI 页面

总览（项目、模型状态、最近训练）、材料工作台（导入与编辑）、分析报告（能力矩阵、引用、问题清单）、模拟面试（当前问题、答案、逐轮反馈、状态控制）、训练档案（历史及报告导出）。桌面左右栏，手机单栏，键盘可操作，按钮在异步任务中禁用。

## 验证与交付

自动化测试覆盖真实数据库、解析、引用剔除、版本冲突、五轮完成、暂停恢复、删除、持久化、导出转义，以及真实 HTTP 协议的 Ollama 测试服务。规则演示用于确定性功能验收，不代替真实模型质量验收。Linux 提供安装、启动、离线依赖准备说明及容器配置。交付课程报告、测试结果、局限与现场演示脚本。
